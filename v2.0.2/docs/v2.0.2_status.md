# Estado del Proyecto: Video API v2.0.2

Este documento resume la arquitectura, controladores y puntos de mejora del sistema de edición de video dinámico.

## 1. Mapa de Controladores

### `Controller.php` (Base)
*   **Propósito**: Clase madre de la que heredan todos los controladores.
*   **Funciones Clave**:
    *   `validarAcceso()`: Verifica que haya una sesión activa.
    *   `_encriptar()` / `_desciptar()`: Maneja el cifrado AES-256 para tokens y el SSO.
    *   `render()`: Inicializa Twig y envía variables a las vistas.

### `AccesoController.php`
*   **Propósito**: Punto de entrada desde el panel principal (SSO).
*   **Acción `default`**: 
    1. Recibe la variable `t` (Base64 Encriptado).
    2. Desencripta: `ID_CLIENTE | TIMESTAMP | SECRETO_SESION | DOMINIO_PERMITIDO`.
    3. Valida que el enlace no tenga más de 60 segundos.
    4. Inicia la sesión de PHP segura.

### `CorrerController.php`
*   **Propósito**: Carga el editor de video para un cliente específico.
*   **Acción `default`**:
    1. Obtiene las plantillas de la base de datos (`video_templates`).
    2. Genera un `proxy_token` único para esta sesión.
    3. Define rutas separadas para assets pesados (públicos) y lógica privada (proxy).
    4. Renderiza `run.twig`.

### `TemplatesController.php`
*   **Propósito**: Gestión CRUD de diseños guardados.
*   **Funciones**:
    *   `saveAction()`: Guarda un nuevo diseño con miniatura Base64.
    *   `updateAction()`: Sobreescribe un diseño existente.
    *   `duplicateAction()`: Crea una copia exacta de una plantilla.
    *   `deleteAction()`: Borrado lógico (`activo = 0`).

### `ProxyController.php`
*   **Propósito**: Servidor virtual de archivos protegidos.
*   **Acción `default`**:
    1. Valida el token dinámico de la URL contra la sesión.
    2. Lee archivos de `private_assets` y los sirve con el `MIME Type` correcto.
    3. Evita que el código fuente JS sea accesible directamente sin sesión.

## 2. Análisis de los 5 Puntos Críticos

### 1. Seguridad (Proxy y Sesión)
*   **Estado**: Estable pero dependiente de sesiones de PHP (IIS puede fallar en archivos temporales).
*   **Mejora**: Migrar a validación por firma (Signed Cookies) para mayor robustez en entornos Windows.

### 2. Estructura de Código (JS/PHP)
*   **Estado**: Acoplamiento medio (Twig inyecta muchas variables).
*   **Mejora**: Centralizar en un objeto `window.CONFIG` y mover lógica de plantillas a un `TemplateService.js` independiente.

### 3. Rendimiento (Fuentes y JSON)
*   **Estado**: Mejorado. El WASM ya no pasa por el proxy (carga desde caché pública).
*   **Mejora**: Implementar precarga de tipografías al abrir el gestor de diseños para evitar saltos visuales.

### 4. Experiencia de Usuario (UX)
*   **Estado**: Funcional. Modal con rejilla de 100px y slidebar lateral.
*   **Mejora**: Eliminar `location.reload()` en favor de actualizaciones AJAX silenciosas para que el gestor se sienta como una App nativa.

### 5. Integración (Apertura desde Panel)
*   **Estado**: Muy bueno. Usa encriptación compartida y validación de dominio.
*   **Mejora**: Implementar un `NONCE` (Número de un solo uso) para evitar ataques de repetición de URL en la ventana de 60 segundos.

## 3. Estructura de Datos JSON (Templates)
Los templates se guardan en la tabla `video_templates` bajo la columna `data_json`.
*   **Formato**: Incluye `ancho`, `alto`, `video_fondo` y un objeto `layout` con todos los bloques y sus coordenadas.
*   **Variables**: Se recomienda el uso de `{{etiqueta}}` para inyectar datos de la BD en tiempo de renderizado con Playwright.
